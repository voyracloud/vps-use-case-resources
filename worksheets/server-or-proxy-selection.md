# Server or proxy selection worksheet

Use this before buying infrastructure. Separate where software runs, how users reach it, and where its outbound requests appear to originate. A proxy does not supply a computer; a server does not automatically satisfy an exit-location requirement.

Compare candidates on these same requirements. Cloud VPS supplies a runtime; a residential IP VPS also has a server-address proposition to verify. Windows VPS serves Windows applications and remote administration. Rotating residential, static ISP, and datacenter proxies supply exits for compatible clients. Do not infer application acceptance from an IP category.

## Fictional example — not a product test

A studio already has a supported computer running a daily supplier report. Its approved API accepts its existing address. The studio records “no additional server or proxy needed,” assigns backups to the operator, and reviews that decision if unattended availability becomes a problem. A second requirement for an inbound demo website would be evaluated separately.

## Limits and sources

A Cloud server with an outbound proxy is not equivalent to a different public inbound address. A VPN, reverse proxy, or managed service may solve a different requirement. Record the actual architecture rather than treating labels as specifications.
